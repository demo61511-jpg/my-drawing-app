Google AI Studio Prompt to Automatically Build and Download Android APK
with GitHub Actions

------------------------------------------------------------------------

Prompt Start Here

————————

Prepare this completed Google AI Studio Android app for automatic debug
APK building and direct APK downloading through GitHub Actions and
GitHub Releases.

IMPORTANT WORKFLOW:

You must first create the GitHub Actions APK build workflow inside this
project.

Do NOT require the GitHub repository to already exist.

After creating the workflow, give me a very short NEXT STEP instruction
telling me to:

1.  Publish/push this completed app to GitHub and create the repository.

2.  Return to this same Gemini chat.

3.  Paste ONLY the full GitHub repository name in this format:

username/repository-name

Example:

myusername/my-android-app

When I later send only a value matching:

username/repository-name

treat it as the GitHub repository identity for this project.

Do NOT edit the Android project again at that point.

Do NOT create another workflow.

Do NOT ask me for the GitHub URL.

Do NOT ask me for the owner and repository separately.

Use the full repository name I provide to generate this permanent direct
APK download URL:

https://github.com/USERNAME/REPOSITORY/releases/latest/download/app-debug.apk

Then give me that completed direct APK download link clearly and tell me
to allow the GitHub Actions APK build and GitHub Release process to
finish before using the link.

------------------------------------------------------------------------

1. Verify Android Gradle Plugin

Before creating anything, confirm that:

gradle/libs.versions.toml

contains exactly:

agp = “9.1.1”

If the AGP version is not exactly 9.1.1:

-   Stop immediately.
-   Report the detected AGP value.
-   Do not create the workflow.
-   Do not modify any file.

If the AGP version is exactly 9.1.1, continue.

------------------------------------------------------------------------

2. Repository modification restriction

Create only:

.github/workflows/build-apk.yml

Do not create, edit, delete, rename, format, upgrade, or replace any
other repository file.

Do not modify:

-   Android source code
-   App design
-   Features
-   Package name
-   Application ID
-   AndroidManifest.xml
-   Resources
-   Dependencies
-   Gradle project files
-   Signing configuration
-   Project settings

The workflow must:

-   Build the debug APK.
-   Preserve the APK as a normal GitHub Actions artifact.
-   Publish the same APK under GitHub Releases.
-   Make the latest successful APK available through one permanent
    direct download URL.

------------------------------------------------------------------------

3. Workflow triggers

Create a GitHub Actions workflow that:

-   Runs automatically on every push to the main branch.
-   Also supports workflow_dispatch.
-   Does not run on pull requests.
-   Uses ubuntu-latest.
-   Checks out the complete repository.
-   Runs all Gradle commands from the repository root.

This means that when I first publish/push this project to GitHub after
you create the workflow, GitHub Actions should automatically begin
building the APK.

------------------------------------------------------------------------

4. Workflow permissions

Add only:

permissions: contents: write

Do not request unnecessary permissions.

Do not use:

-   Personal access token
-   Repository secret
-   External API key
-   Deployment key
-   Custom credential

Use only the workflow’s built-in GitHub token:

${{ github.token }}

------------------------------------------------------------------------

5. Java setup

Set up Temurin Java 17 using:

actions/setup-java

Java must be configured before Gradle or any Gradle command.

Add a step named:

Verify Java environment

That step must:

-   Run java -version.
-   Print JAVA_HOME.
-   Detect the active Java major version.
-   Confirm the active Java version is 17 or newer.
-   Fail clearly if Java is lower than 17.
-   Fail clearly if Java cannot be detected.

------------------------------------------------------------------------

6. Gradle setup

Set up exactly:

Gradle 9.3.1

using:

gradle/actions/setup-gradle

Do not use:

-   Gradle 8.13
-   Repository Gradle wrapper
-   ./gradlew
-   gradlew
-   latest
-   current
-   release-candidate
-   nightly
-   Any Gradle version other than exactly 9.3.1

Run all Gradle commands from the repository root.

------------------------------------------------------------------------

7. Temporary debug keystore

Before building, add a step named:

Create temporary debug keystore

That step must:

-   Check whether ./debug.keystore already exists.
-   Generate it only when it is missing.
-   Use keytool from the configured Java installation.

Use exactly:

Keystore password:

android

Key alias:

androiddebugkey

Key password:

android

Distinguished name:

CN=Android Debug,O=Android,C=US

Algorithm:

RSA

Key size:

2048

Validity:

10000 days

After generation:

-   Confirm ./debug.keystore exists.
-   Fail clearly if it cannot be created.

Never:

-   Commit the keystore.
-   Cache the keystore.
-   Print the keystore.
-   Expose its contents.
-   Upload the keystore as an artifact.
-   Upload the keystore to GitHub Releases.
-   Preserve the keystore outside the temporary GitHub Actions runner.

------------------------------------------------------------------------

8. Build the debug APK

Build the debug APK using exactly:

gradle :app:assembleDebug –stacktrace –no-daemon

Do not replace this command with:

-   ./gradlew
-   gradlew
-   assembleRelease
-   bundleRelease
-   assemble
-   build
-   Any other Gradle build command

------------------------------------------------------------------------

9. Verify the APK

After the build, verify that this exact file exists:

app/build/outputs/apk/debug/app-debug.apk

If the exact file is missing:

-   Search only inside app/build/outputs/apk.
-   Print APK paths discovered there.
-   Do not search the entire repository.
-   Do not select a release APK.
-   Do not select an Android test APK.
-   Do not select an APK from another module.
-   Do not upload or release an unrelated APK.
-   Fail clearly.

Confirm that the APK:

-   Exists.
-   Is a regular file.
-   Is not empty.
-   Has the .apk extension.
-   Is exactly:

app/build/outputs/apk/debug/app-debug.apk

------------------------------------------------------------------------

10. Upload GitHub Actions backup artifact

After APK verification, add a step named:

Upload debug APK artifact

Use:

actions/upload-artifact

Upload only:

app/build/outputs/apk/debug/app-debug.apk

Name the Actions artifact exactly:

app-debug-apk

Configure artifact upload to fail if the APK is missing.

Do not upload:

-   debug.keystore
-   Credentials
-   Source code
-   Gradle caches
-   Build caches
-   Configuration files
-   Secrets
-   Logs containing sensitive information
-   google-services.json
-   Firebase configuration
-   Signing files

The normal Actions artifact must remain available as a backup even after
GitHub Release publishing is added.

------------------------------------------------------------------------

11. Prepare APK release asset

After the Actions artifact is uploaded successfully, add a step named:

Prepare APK release asset

Create a temporary directory inside the GitHub Actions runner.

Do not create or commit this directory in the repository.

Copy only:

app/build/outputs/apk/debug/app-debug.apk

into the temporary directory.

The GitHub Release asset filename MUST ALWAYS be exactly:

app-debug.apk

Do not add:

-   Repository name
-   Workflow run number
-   Workflow attempt
-   Commit SHA
-   Date
-   Timestamp
-   Version number
-   Random characters

Every GitHub Release must contain its APK using the same asset filename:

app-debug.apk

Do not compress the APK.

Do not place the APK inside a ZIP.

Do not rename the original APK inside the repository.

Do not modify the original APK.

Export the prepared release asset path through GITHUB_OUTPUT.

------------------------------------------------------------------------

12. Publish APK to GitHub Releases

After the normal Actions artifact is uploaded and the release asset is
prepared, add a step named:

Publish APK to GitHub Releases

Use:

gh release create

Do not use an unverified third-party GitHub Release action.

Authenticate using:

GH_TOKEN: ${{ github.token }}

Before release creation:

-   Run gh –version.
-   Confirm GitHub CLI is available.
-   Confirm the prepared APK exists.
-   Confirm it is non-empty.
-   Confirm it ends in .apk.
-   Confirm the release asset filename is exactly app-debug.apk.
-   Do not attempt release creation if APK validation fails.

------------------------------------------------------------------------

13. Unique GitHub Release tag

Every workflow execution must receive a unique release tag using both:

GITHUB_RUN_NUMBER

and:

GITHUB_RUN_ATTEMPT

Use this tag format:

debug-apk-build-GITHUB_RUN_NUMBER-GITHUB_RUN_ATTEMPT

Example:

debug-apk-build-12-1

Construct the tag dynamically at workflow runtime.

Do not use a fixed tag such as:

-   latest
-   debug
-   build
-   v1
-   apk

Do not overwrite, move, delete, or reuse an existing release tag.

The unique tag must prevent conflicts when:

-   A new commit is pushed.
-   The workflow is run manually.
-   A failed workflow is rerun.
-   Another run attempt occurs.

Attach only:

-   Draft

The release Assets section must contain:

app-debug.apk

https://github.com/USERNAME/REPOSITORY/releases/latest/download/app-debug.apk

-   A run-number URL

16. Release failure protection

The GitHub Actions artifact must upload BEFORE release publishing
begins.

Configure the release publishing step with:

continue-on-error: true

Assign an id to the release step so its outcome can be checked
afterward.

If release publishing fails:

-   Do not remove the successfully built APK.
-   Do not remove the Actions artifact.
-   Do not falsely report release success.
-   Do not create a duplicate fallback release.
-   Do not use another release action.
-   Clearly report that the release failed.
-   Clearly state that the Actions artifact named app-debug-apk remains
    available.

Release failure must not make a successful APK build appear to have
failed if the APK and Actions artifact were successfully generated.

-   Print the release tag.
-   Print the release title.
-   Print the release page URL.
-   Print the APK filename:

-   Label it:

If release publishing failed:

-   Print a clear warning.
-   State that the APK build succeeded if it did.
-   State that app-debug-apk remains available.
-   Do not falsely claim the new APK is available through the direct
    latest-release link.

Authenticate gh commands using:

GH_TOKEN: ${{ github.token }}
